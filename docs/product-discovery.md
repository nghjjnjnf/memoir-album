# 产品探索底稿

## 1. 初始愿景

帮助老年人通过与 Agent 的持续对话，回顾、理解并保存自己的一生；支持上传关键时期的照片和补充内心描述；在反复确认和共同修改后形成专属自传，并生成书名与封面。

## 2. 初步价值判断

这个产品不应只是“把聊天整理成长文”，而应同时承担四个角色：

1. 温和而有耐心的访谈者；
2. 帮助唤起记忆、梳理时间线的引导者；
3. 忠于本人表达、避免擅自编造的编辑；
4. 让本人及其授权家人共同保存记忆的出版助手。

## 3. 候选核心流程

1. 建立人物档案、称呼方式和沟通偏好；
2. 进行低压力的首次对话，建立信任；
3. 先形成“人生地图”，再选择阶段或主题深入访谈；
4. 每次访谈后提炼事件、人物、地点、时间、情绪和未确认信息；
5. 邀请本人确认、更正或暂时跳过敏感内容；
6. 上传照片，记录照片中的人物、时间、地点、故事和使用授权；
7. 按章节生成草稿，并允许口述式反馈和反复修改；
8. 进行全书一致性检查、事实确认和隐私确认；
9. 生成书名、序言、目录、封面与可导出的成书版本。

## 4. 必须深入讨论的产品问题

### 用户与使用场景

- 第一用户是老人本人、子女，还是养老/社区服务人员？
- 老人会独立操作手机/平板，还是主要由家属陪同？
- 产品主要用于家庭留存、正式印刷，还是兼顾公开出版？
- 首发面向哪种语言、地域和文化背景？

### 交互方式

- 语音、文字、视频访谈分别占多大比重？
- 一次访谈应持续多久，怎样识别疲劳并主动暂停？
- 是按年代推进，还是从最想讲的故事开始？
- 如何处理“记不清”“不想谈”“以后再说”？

### 内容真实性与作者权

- Agent 可以润色到什么程度，怎样保留讲述者原本的声音？
- 推断出的时间和因果关系如何标注并请求确认？
- 家属补充内容与本人叙述冲突时，以谁为准，如何并存？
- 哪些内容可以进入书稿，哪些只保留为私密记忆？

### 隐私、安全与伦理

- 如何获得持续、可撤回的授权？
- 如何处理创伤、家庭秘密、已故或在世第三人的隐私？
- 如何避免 Agent 诱导、评判、诊断或制造虚假记忆？
- 数据由谁拥有，如何导出、删除、继承或转交？

### 成书标准

- 最终成品是完整传记、口述史、回忆录，还是照片故事书？
- 一本书的目标篇幅、章节数和制作周期是什么？
- 照片如何修复、排版、加注释并确认版权？
- 是否需要 PDF、电子书和按需印刷版本？

## 5. 当前待确认的第一组决策

1. 核心使用者与购买者是谁；
2. 典型使用方式是老人独立使用还是家属陪伴；
3. 首个版本要交付哪一种“书”；
4. 语音是否是首要交互入口；
5. 产品希望更像“温暖的陪伴者”还是“专业的口述史访谈员”。

## 6. 暂不锁定

在上述问题明确前，暂不锁定模型、框架、数据库、部署方式和具体页面结构。

## 7. 已确认的首版产品方向

首版采用“照片驱动的章节式自传”，而不是要求使用者先完成一整套人生访谈。

核心闭环为：

1. 老人选择并上传一张或多张相关照片；
2. 通过语音讲述照片背后的时间、人物、地点、事件和感受；
3. Agent 根据缺失信息进行少量、自然的追问；
4. 将照片和讲述整理为某个人生阶段的一篇章节草稿；
5. 老人通过听读或家属协助确认、更正和补充；
6. 生成可独立阅读和分享的章节；
7. Agent 根据当前故事推荐下一张照片、下一位人物或下一个问题；
8. 新故事不断加入，最终组合成完整自传。

### 产品价值

- 老人每次只需要面对一张熟悉的照片，启动成本低；
- 每次对话都能快速形成一个看得见的成果；
- 不必严格按年份回忆，可以从记忆最鲜活的地方开始；
- 单章分享能够获得亲友反馈，也可能唤起新的共同记忆；
- 多个独立故事可在后期重新排序、合并为完整人生脉络。

### 单章应保存的核心信息

- 原始照片及照片使用授权；
- 老人的原始语音和转写文本；
- 大致时间或人生阶段；
- 地点、人物及人物关系；
- 发生了什么；
- 当时的感受和现在回看时的感受；
- Agent 的问题与老人的回答；
- 尚未确认的信息；
- 章节正文、版本历史和确认状态；
- 分享范围、分享链接状态和读者反馈。

### 首版必须包含的保护机制

- Agent 不确定时应提问或标注，不得擅自补全事实；
- 正文发布前必须由老人或其授权协作者确认；
- 每章可以单独设置为私密、指定亲友可见或持链接可见；
- 分享可以随时撤回，且默认不允许读者转发或下载原图；
- 老人可以保留“只想记录但不想写进书里”的内容；
- 家属补充与老人原始叙述需要区分来源。
