# 本地 MVP 实现状态

更新日期：2026-08-31  
版本：0.3.0

## 1. 本轮范围调整

根据当前决定，本轮先验证照片、文字访谈和章节生成，不实现语音。

本轮纵向闭环为：

```text
创建自传项目并选择人称
→ 上传一张照片
→ 用文字讲述照片故事
→ Memory Agent 提取事实
→ Interview Agent 每次追问一个问题
→ Chapter Agent 生成章节
→ Review Agent 审校
→ 用户提出修改
→ 生成不覆盖原稿的候选版本
→ 用户采用、继续调整或放弃
→ 采用后创建不可变新版本
→ 用户确认
```

与原计划相比，本轮主动延后：ASR、TTS、浏览器录音、照片视觉模型、PostgreSQL/pgvector、向量数据库、微信分享卡片和微信小程序。当前已经实现本地方法卡检索和本地私密分享页。

## 3. 当前数据模型

SQLite 中包含：

- `projects`：自传项目与默认人称；
- `photos`：原文件名、本地文件名、类型和章节关系选择；
- `interview_sessions`：状态和回答轮数；
- `interview_turns`：不可变对话记录；
- `memory_facts`：事实类型、值、状态、证据回答、敏感度、不入书标记和取代关系；
- `chapters`：章节当前状态和当前版本指针；
- `chapter_versions`：不可变正文、来源快照、审校报告和确认时间；
- `chapter_revision_candidates`：尚未采用的修改稿、基准版本、修改指令、审校结果和记忆变更提案；
- `chapter_photos`：章节和照片关系；
- `share_links`：绑定具体章节版本的私密链接及撤回状态；
- `model_runs`：关联项目的模型运行审计记录。

## 4. DeepSeek 使用方式

模型 Gateway 调用：

```text
POST https://api.deepseek.com/chat/completions
```

每个 Agent 要求返回 JSON 对象，系统会去除可能的 Markdown 代码围栏并解析。空结果、HTTP 错误或非法 JSON 会重试一次，仍失败则使用本地保守结果并记录错误。

当前实现不把照片发送给 DeepSeek。原因是本轮只接入文本 Chat Completions，并且在引入明确支持图片的模型前，不能让系统假装看懂照片。

## 6. 当前验收结果

48 项自动测试已验证以下核心链路（含边界与回归场景）：

- 创建项目；
- 上传图片；
- 完成三轮文字讲述；
- 保存事实及证据；
- 进入可成稿状态；
- 生成第一版章节；
- 修改并保留第二版；
- 确认当前版本；
- 更正事实与排除敏感事实；
- 第三人称生成；
- 写作方法检索快照；
- 审校失败禁止确认；
- 第二张照片合并后保留旧版本和旧分享；
- 私密分享、版本绑定和撤回；
- 项目导出及照片、分享、模型记录级联删除。

上述结论是早期 Mock 基线；2026-08-24 已补做本地 DeepSeek 真实链路测试，结果见下一节。

## 7. 2026-08-24 整书关联扩展

新增整书导演、跨章改写、定向衔接编辑、章节事实链接、整书连续性审校和不可变 `book_editions`。真实周桂兰六章测试完成 6/6 章改写、17 条跨章事实溯源和 4 条暗线；DeepSeek V4 结构化任务已显式关闭默认思考模式，避免输出预算全部消耗在 `reasoning_content`。

自动测试现为 26 项全部通过。模型审校通过后，人工终检仍发现少量称谓、位置与动作动词漂移，因此整书自动出版能力标记为“部分完成”：可以生成高质量候选稿，但确认前仍需编辑或用户终检。详见 `../../outputs/周桂兰整书关联逻辑测试报告.md`。

## 8. 2026-08-31 候选修改与记忆隔离

章节修订不再立即替换当前草稿。系统先保存独立候选稿，用户可以继续调整、放弃或采用；采用时才创建新的不可变章节版本。文学风格指令不会修改人生记忆；明确的“把‘原内容’改成‘正确内容’”会形成记忆变更提案，采用后以 append-only 方式写入新事实并撤回旧事实，年份更正同步更新时间线。完整自动回归现为48项通过，并完成一次周桂兰真实 DeepSeek 候选生成—放弃测试，章节当前版本指针保持不变。
