# MVP 产品设计：从照片到人生章节

## 一句话产品定义

老人上传一张旧照片，用语音讲述照片背后的故事；Agent 通过温和追问补足细节，将其写成可确认、可分享的人生章节，并继续引导老人发现下一段记忆。

## 核心对象

### 照片记忆

一次创作的起点。可以是一张照片，也可以是一组属于同一事件或时期的照片。

### 访谈会话

围绕照片展开的语音讲述与追问过程。允许分多次完成，不要求一次讲完。

### 人生章节

由照片记忆生成的独立故事。章节可以先独立存在，之后再归入某个人生阶段并调整顺序。

### 分享页

面向亲友的轻量阅读页面，展示经授权的照片与章节正文。读者可以在允许时提供文字或语音线索，但不能直接改写老人的正文。

## 老人端主流程

1. 点击“讲讲这张照片”；
2. 从相册选择照片或直接拍摄纸质照片；
3. Agent 先提出一个容易回答的问题，例如“这张照片里都有谁？”；
4. 老人按住或点击按钮开始讲述；
5. Agent 每轮只问一个问题，并允许“记不清”“跳过”“今天先到这里”；
6. 信息足够后，Agent 告知“我先把这段故事整理出来”；
7. 展示章节草稿，同时提供语音朗读；
8. 老人用自然语言提出修改，例如“这里不是春天，是秋天”；
9. 确认后保存章节，并由老人决定是否分享；
10. Agent 推荐下一步，但不制造完成压力。

## 建议的追问框架

追问不是固定问卷，而是围绕缺失信息动态选择。优先级建议如下：

1. 照片里是谁；
2. 这是在哪里；
3. 大约是什么时候；
4. 当时发生了什么；
5. 为什么这张照片被保存到现在；
6. 当时有什么感受；
7. 如今回头看，有什么不同的理解；
8. 是否还有相关的人、照片或物件值得继续讲。

一次访谈只追问少量关键问题，避免像审讯或填表。

## 章节生成规则

- 仅把老人明确说过或后来确认的内容写成事实；
- 时间不确定时使用“大约在……”“那几年”等真实表达；
- 保留老人的常用词、语气和价值判断；
- 文学化描写不得凭空加入天气、动作、对话或心理活动；
- 对敏感人物和事件，在分享前再次确认是否保留；
- 原始语音、转写和成稿相互关联，方便追溯与修改；
- 章节可标记为草稿、待确认、已完成、已分享。

## 分享与协作

- 每章单独生成分享入口，不默认公开整本自传；
- 默认私密，分享由老人或授权协作者主动开启；
- 支持撤销链接和重新生成链接；
- 亲友反馈以“补充线索”存在，需老人确认后才能进入章节；
- 后续可支持邀请特定家人共同补充同一张照片的多视角记忆。

## 章节之后的继续引导

Agent 可以基于已有内容提供三类温和建议：

- 照片线索：“您还保存着那次搬家前后的照片吗？”
- 人物线索：“刚才多次提到您的姐姐，要不要讲讲她？”
- 时间线索：“我们已经记下工作后的故事，下次想不想聊聊刚参加工作的时候？”

老人始终可以忽略建议、自选照片或暂停项目。

## MVP 范围建议

首版聚焦：照片上传、语音讲述、动态追问、章节生成与修改、语音朗读、章节私密分享、继续讲述引导。

首版暂缓：复杂排版印刷、公开社区、照片 AI 修复、多位讲述者自动融合、完整家谱、视频访谈和商业出版流程。

## 下一轮需要确定

1. 每个章节主要分享给谁，以及是否允许对方留言或补充故事；
2. 一个章节更偏短篇照片故事，还是较完整的人生阶段叙事；
3. 老人独立操作与子女代操作之间的权限关系；
4. Agent 默认使用怎样的称呼、语言风格和追问节奏；
5. 照片可能缺少准确日期时，如何组织全书顺序。
