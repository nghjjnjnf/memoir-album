# 事件级时间记忆与归属设计

状态：MVP 已实现  
更新日期：2026-08-30

## 设计原则

系统管理的是一个人的事件网络，而不是简单地给每张照片填写一个年份。照片说明、文字回复和后续语音转写都进入同一条事件提及解析链路；每条时间必须保留用户原文、来源、语义角色和相对时间锚点。Assistant 的复述不能成为事实来源。

## 数据模型

`timeline_events` 保存照片主要记录的事件，并增加 `time_locked`、`time_source_type` 与 `time_source_id`。即使主时间只有“小学”“初三”等人生阶段，也视为已经建立，不允许后来出现的具体年份覆盖。

`event_mentions` 以追加方式保存每次时间提及，支持绝对年份、年份范围、相对时间、年龄和人生阶段。`temporal_role` 区分：

- `photo_capture_event`：照片主要事件时间；
- `supporting_time`：对主时间的重复支持；
- `later_related_event`：后来、再次、重访等后续事件；
- `related_event`：同一讲述中的其他时期；
- `time_correction`：用户明确表示“记错了”“不是……应该是……”后的更正。

`event_relations` 保存 `revisit_of`、`related_to` 等事件关系。相对时间同时保存讲述发生年份作为锚点，例如2026年讲述的“去年”解析为2025年，但原文“去年”仍保留。

## 写入规则

1. 上传照片后立即解析照片说明，不等待第一次访谈回复。
2. 每次用户回复先拆出事件提及，再调用 Memory Agent 提取普通事实。
3. “这张照片、拍摄、拍下”等表达指向照片事件；“后来、再次、又去、重回、重返”等表达优先建立关联事件。
4. 新时间与已锁定主时间不一致时，默认追加关联提及，不覆盖主时间。
5. 只有明确的用户更正可以替换锁定时间；旧提及仍保留以供审计。
6. 时间线刷新只使用主事件事实推导主时间，`related_event_mention` 不参与主年份计算。
7. 对旧项目启动幂等回填：按原始照片说明和用户原话重新建立事件提及，不使用 Assistant 文本。

## Agent 共享与接口

时间线接口为每个事件返回 `event_mentions` 和 `related_events`。共享 `LifeContextSnapshot` 也携带关联事件提及，使访谈、章节写作、人物整理和整书导演看到一致的事件关系，但不会把关联事件的年份误作照片年份。

## 验收结果

自动测试覆盖照片说明提前锁定、人生阶段保护、同一句多事件拆分、相对时间锚定、后来重访、明确更正、跨照片年份回填和乱序上传排序。当前完整回归为 `36 passed`。

上海交通大学案例已从错误的“2025年照片”修复为：主照片时间为“小学”，来源为照片说明；2025年作为 `later_related_event` 保存，不再覆盖照片时间。
