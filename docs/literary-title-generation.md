# 上传阶段文学标题生成设计

## 目标

照片上传后不再把用户说明或文件名直接当作页面标题。用户没有填写标题时，系统在识图完成后立即结合照片观察、用户提示和当前人物／事件／关键事实记忆，生成一个可以直接展示的文学标题；即使此时尚未开始访谈，也能让照片以“故事入口”而不是“文件记录”的方式出现。

## 处理流程

`保存原图 → 后台识图 → 创建人生事件 → 读取共享人生记忆 → Title Agent 生成 → 质量门禁 → 保存标题版本 → 时间线展示`

Title Agent 只能把识图中的人物数量、构图、物件、场景和 OCR 当作候选线索。未经用户口述确认的地点、年代和人物身份不得写成确定事实；共享记忆与视觉判断冲突时，以用户已确认或明确讲述的记忆为准。模型调用失败、输出过长或仍是“这是……的照片／在某地旅游”一类文件名式标题时，系统使用本地含蓄标题兜底，不阻断上传和访谈。

用户主动填写的标题同时作为首轮访谈上下文。系统会保守识别其中明确出现的时间和地点：已经提供的字段不再反问，而是转向拍摄缘由、同行人物或事件经过。该信息也会留下事件提及证据；视觉模型只能补充尚未知的槽位，不能覆盖用户输入。

## 标题层级

页面只展示一个标题，但保留不同层的数据职责：

1. 用户上传时填写或后来更正的标题；
2. 章节成稿后的文学标题；
3. 上传识图阶段自动生成的文学标题；
4. 用于内部检索和事实归档的事件名称。

优先级固定为 `用户命名 > 章节标题 > 自动标题 > 归档名称`。章节生成可以自然升级自动标题，但永远不能覆盖用户明确命名。

## 可追溯性

`event_title_versions` 采用追加版本，记录标题、来源（`user`、`title_agent`、`local_fallback`）、生成阶段、简短理由、照片 ID、视觉摘要、用户说明、共享记忆快照 ID 和实际使用的事实 ID。时间线 API 同时返回 `archival_title`、`display_title`、`title_source` 与 `title_versions`，便于前端稳定展示和后续评测。

## 验收

- 空标题上传后立即出现文学标题；
- Title Agent 输入同时包含照片观察与共享人生记忆；
- 用户标题不触发自动改写，并在章节生成后仍保持最高优先级；
- 时间线更正的事件名称被记为用户标题；
- 模型输出不合格或调用失败时安全降级；
- 原始事件名称不因展示标题变化而丢失。
